How the AGL Platform Works

A behind-the-scenes look at what happens when you log in, play a match, and log out — and how your AG Champion runs safely inside an isolated sandbox on the platform's own servers.

Looking for the setup steps? See How to register your AG Champion.

Model Repo or Dataset Repo — What Goes Where?

Hugging Face accounts can hold several kinds of repos. Here's what each one is used for.

Model Repo (required, Gated)

Holds your code and config files (and weights, if you keep them there). The platform downloads it to its own servers and runs it inside an isolated Docker sandbox to generate moves. It must be Gated, and the platform's account ArtificialGladiatorLeague must be approved on it.

Dataset Repo (optional, Public)

Used for any supporting data files your model needs at inference time (e.g. opening books, precomputed tables). It is mounted read-only next to your model inside the sandbox.

In short: your files are copied to the platform's servers and executed inside a locked-down Docker sandbox on the platform's own infrastructure. You never need to host a Space, endpoint, or any always-on server.

How Your AG Actually Plays

A common question: "When I play, where does my model actually run?" It runs in a sandboxed Docker container on the platform's own servers — there is nothing for you to host or keep running.

The container is hardened and has these limits (the values below are the platform defaults; they are server settings):

  • No network access at all.
  • Read-only filesystem. Your model, your data and the runner are mounted read-only; the only writable place is a small temporary folder (/tmp, 64 MB).
  • Locked-down process: it runs as an unprivileged user, with all Linux capabilities dropped and privilege escalation disabled.
  • Resource limits: 512 MB of memory, 1 CPU and 128 processes/threads.
  • Time limit: 30 seconds per move. A cold start (starting the container and running your load()) is allowed up to 120 seconds.

The container is kept warm. The platform keeps one sandbox container per model and reuses it between moves, so your load(ctx) runs once and each move only costs a get_move(state, fen, player) call. The container is not thrown away after every move.

  • It is started ahead of time when you open the Lobby or a game page, so the first move is not a cold start.
  • An idle container is stopped automatically (after 15 minutes without a move, by default) and started again when needed.
  • It is restarted if your model files change, the container dies, or a move times out.
  • Your code never runs outside the sandbox. If the sandbox itself is unavailable, that is treated as a platform problem and no random move is substituted for it.
1

When You Log In

Logging in prepares your private workspace on the server and makes sure your registered models are available locally.

  • For each model you registered, the platform looks for a copy of your model repo in its shared Hugging Face cache. If there is none yet, it downloads one now; if there is, nothing is downloaded. A problem here does not block your login.
  • Private model and data folders are created for your account (Chess and Breakthrough), and a per-session workspace folder is created for you.
  • Your data repo files are not downloaded at this point. They are fetched the first time your model is loaded into a sandbox container, which normally happens in the background when you open the Lobby (where login lands you) or a game page.
2

While You Play — How a Move Is Generated

Every single move, for both players, is generated live by calling your model in its sandbox container — moves are never precomputed.

Board position sent > Your model's get_move runs in the warm sandbox > Move validated > Game state updated
  • If your model answers within the move time limit with a legal move, that move is used (shown at once, or after the configured "thinking time" target, whichever is longer).
  • If it is too slow, raises an error, returns nothing, or returns an illegal move, the platform plays a random legal move for that turn (captures preferred) so the game keeps going. When a move times out, the container is restarted.
  • Exception: if your model's last model check failed, no random move is played and you forfeit the game.
  • The time your model spends thinking is deducted from your game clock.
3

When You Log Out

The private workspace created for you is removed from the server.

  • Your per-session workspace folder and your private model and data folders on the server are deleted. That includes the copy of your data repo files, which is downloaded again the next time your model is loaded.
  • You are removed from the online-players counter.
  • Your Hugging Face repos are not touched. They remain exactly as you left them and remain the source of truth.
  • Your Elo, match history and registered repo links are stored in your profile and are not affected by logging out.
  • Sandbox containers are not tied to your login. An idle one is stopped automatically after its idle timeout.

Why It's Built This Way

Safe by default

Submitted code runs in a container with no network, a read-only filesystem and CPU, memory and time limits, so a model can neither reach out nor change anything on the server.

Fair, identical treatment

Every AG Champion — from a beginner's random-move bot to a Grandmaster-rated neural net — is called the same way, through the same load / get_move contract, inside a sandbox with the same limits.

Fast moves

Keeping one container warm per model means your model is loaded once, not before every move, so the move time is spent thinking rather than starting up.

You stay in control

Your code stays in your own Hugging Face repo, which is Gated: only accounts you approve, including the platform's ArtificialGladiatorLeague account, can read it. Ownership is proven with an AGL_VERIFY.txt file in your repo.
