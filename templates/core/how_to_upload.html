Step-by-step guide

How to Register Your AG Champion

This guide gives you the exact steps to register your Artificial Gladiator Champion (AG Champion), the program that plays games for you on the Artificial Gladiator League (AGL) platform. You store your files in a repo on Hugging Face, connect that repo on your Profile, prove that you own it, and run a built-in check. Then your AG Champion can play in games and tournaments.

Want the background first? Read How it works. It explains what the platform does and lists the rules that affect you.

What you'll need

  • An account on this platform. Step 1 creates it.
  • A Hugging Face account. Hugging Face is the website where your files are stored.
  • A Python program, your AG Champion. The easiest start is to copy a working example (Step 2) and edit it (Step 3).

Important

Three rules can cost you games or a tournament place. Read them before you start:

  • Repo access: your repos need the right visibility, and you must approve the platform's account.
  • Tournament qualification: you need {{ tournament_min_rated_games|default:30 }} rated games before you can join tournaments.
  • Version pinning: new commits in your repos can disqualify you or block tournament entry.

The 7 steps at a glance

This is the shortest path from nothing to a working, registered AG Champion. The steps below use the same numbers and the same order. Do them one after the other.

  1. Create your accountFill in the registration form and activate your account by email.
  2. Create your Hugging Face reposCopy the working example, make your model repo Gated, and approve ArtificialGladiatorLeague.
  3. Write your AG ChampionEdit the example code and add the config files.
  4. Register your reposOpen the Gladiator tab on your Profile, enter your model repo, and click the gold button Save and verify.
  5. Prove you own your reposAdd AGL_VERIFY.txt with the code shown on the Gladiator tab, then click Verify Ownership.
  6. Run DiagnosticsOpen the Diagnostics tab and click Run diagnostics. Fix what it reports and run it again until it says RESULT: your model works correctly.
  7. Play and competePlay rated games in the Lobby and enter tournaments. The Lobby is labelled "Hatzar Grutaot" in the menu.

Step 2: Create your Hugging Face repos

A repo is a folder of files stored on Hugging Face. You need a model repo, and optionally a data repo. What each one holds is explained in Your two repos. {% if guest_mode_enabled %}

The model repo must be Gated (only accounts you approve can read it), and you must approve the platform's Hugging Face account ArtificialGladiatorLeague in the repo's Access settings. Without both, saving your repo fails. Why: Repo access.

Next step: Step 3: Write your AG Champion

Step 3: Write your AG Champion

Your AG Champion is Python code that receives a board position and returns a legal move string. The logic inside is entirely up to you. The platform downloads your code and runs it in a sandbox on its own servers, so you need no external hosting or always-on server.

Tip

Any algorithm is welcome. Monte Carlo Vector Search (MCVS), Minimax, alpha-beta pruning, MCTS, policy networks, value networks, reinforcement learning, opening books, endgame tablebases, hybrid approaches: if it returns a legal move string within the time limit, it qualifies.

Important

Your code runs with no network, read-only files, a fixed set of libraries and a move time limit. Check Sandbox limits before you write code. For example, calls such as requests or urllib fail.

What to do
  1. In your model repo, edit the entry-point file so that it defines load(ctx) and get_move(state, fen, player) (see below).
  2. Add the two config files.
  3. Save your files as UTF-8. The platform also tolerates common Windows encodings (cp1255, cp1252) and reports a warning when it has to fall back.
Where
In your model repo on Hugging Face, on the main branch.
How you know it worked
Steps 5 and 6 show the result. The platform runs the model check on your code when you verify ownership, and Diagnostics repeats it.
If it fails
Model check failed, Invalid move returned, Data files not loading

The contract: load(ctx) and get_move(state, fen, player)

Your entry-point file must define both functions. There is no other interface.

  • state = load(ctx) is called once when your AG Champion is loaded. Open your weights, opening books and other files here and return whatever you want to keep. It is passed back to you as state.
  • ctx.model_dir and ctx.data_dir are real, read-only folders (pathlib.Path) that hold your model repo files and your data repo files. ctx.data_dir is None when no data files are available. The platform never opens your data files for you. Read them yourself inside load().
  • move = get_move(state, fen, player) is called for every move. fen is the position, written as FEN text. player is "w" or "b" (the side to move). Return the move as a plain string.

By default the platform imports <game>_mcvs.py (chess_mcvs.py for Chess, breakthrough_mcvs.py for Breakthrough). To use a different file, name it in entrypoint in config_model.json.

chess_mcvs.py (Chess example) 
# chess_mcvs.py - at the root of your model repo
import random

import chess


def load(ctx):
    # Called once. ctx.data_dir is None if no data files are available.
    state = {"opening_book": None}
    if ctx.data_dir is not None:
        book = ctx.data_dir / "opening_book.txt"
        if book.exists():
            state["opening_book"] = book.read_text(encoding="utf-8").splitlines()
    return state


def get_move(state, fen, player):
    # Return one legal move in UCI notation, for example "e2e4".
    board = chess.Board(fen)
    legal = list(board.legal_moves)
    if not legal:
        return ""
    # ---- replace this with your real model ----
    return random.choice(legal).uci()

Move format

What your get_move must return
GameFormatExamples
Chess UCI notation. Not SAN such as Nf3. e2e4, or e7e8q for a promotion
Breakthrough Exactly four characters: the square you move from followed by the square you move to. a2a3, b2c3
Breakthrough: position format, movement rules and starter code Reference

The position is a FEN-like string with rank 8 first (a rank is a row of the board), W for white pieces, B for black pieces, digits for empty squares and the side to move at the end. The start position is BBBBBBBB/BBBBBBBB/8/8/8/8/WWWWWWWW/WWWWWWWW w.

A piece moves one square forward, straight (only onto an empty square) or diagonally (onto an empty square or an enemy piece). White moves toward rank 8, black toward rank 1.

    return {}


def get_move(state, fen, player):
    # fen example: "BBBBBBBB/BBBBBBBB/8/8/8/8/WWWWWWWW/WWWWWWWW w"
    # Return "from-square" + "to-square", for example "a2a3".
    return "a2a3"
Tip

There is no web server, Space or hosted endpoint to run. Your model repo stays Gated, and the platform only needs the read access you approve.

Add the config files

Two small JSON files describe your repos. Add config_model.json to your model repo, and config_data.json to your data repo if you use one. The model check does not require them. Without config_model.json, the platform uses <game>_mcvs.py, or imports every .py file if that file does not exist. The Repo File Status panel on the Gladiator tab and the Diagnostics tab do need them. They read files from config_model.json (model repo) and, if you use a data repo, from config_data.json (data repo). They report a problem when a file cannot be read or lists no files.

Important

Each file must be valid JSON: no comments and no trailing commas. A listed entrypoint or modules file that does not exist is reported as a problem.

config_model.json (root of the model repo)

config_model.json 
{
  "schema_version": 1,
  "entrypoint": "chess_mcvs.py",
  "data_files": ["opening_book.txt"],
  "requirements": ["numpy", "python-chess"],
  "files": ["chess_mcvs.py"]
}
Fields of config_model.json
FieldTypeNeeded?What it does
schema_versionintegerOptionalManifest format version. Use 1.
entrypointstringOptionalThe .py file to import. Default: <game>_mcvs.py. If that file does not exist either, every .py file in the repo is imported.
moduleslist of stringsOptionalAn older alternative to entrypoint. Every listed file is imported and the last one wins.
data_fileslist of stringsOptionalFiles your AG Champion expects to find in your data repo. The model check fails if one of them is missing.
requirementslist of stringsOptionalInformational only. Nothing is installed.
fileslist of stringsAdd itThe files that must exist in the model repo. Used by the Repo File Status panel and by Diagnostics, which report a problem if the list is missing or empty. The sandbox does not use it.

config_data.json (root of the data repo, only if you use one)

config_data.json 
{
  "files": ["opening_book.txt"]
}

files lists every file that must exist in the data repo. It is read from the main branch and is used by the Repo File Status panel and by Diagnostics, which report a problem if the file is missing or lists no files. Keep it consistent with data_files in config_model.json.

Step 5: Prove you own your repos

Before your AG Champion can play, you must prove that you own the repos. You do this with a small file that contains the verification code the platform gave you in Step 4.

Important

Put AGL_VERIFY.txt at the root of the repo on the main branch, not inside a subfolder.

Warning

Each time Verify Ownership, Re-check Ownership or Save and verify passes, the platform runs the model check again and your rated-games count goes back to 0. Click it only when you need to. See Tournament qualification.

What to do
  1. On Hugging Face, create a file named AGL_VERIFY.txt at the root of your model repo (main branch). It must contain exactly the verification code. Surrounding whitespace or a trailing newline is ignored.
  2. If you also set a data repo, add the same file with the same code to the root of the data repo.
  3. On the Gladiator tab, click Verify Ownership. It is shown as Re-check Ownership once you are verified.
Where
The file goes into your repo on Hugging Face. The buttons Copy file name and Copy code on the Gladiator tab give you the file name and the code. The Verify Ownership button is on the same tab.
How you know it worked

The platform account reads the file from each repo. When the model repo and the data repo (if set) both match, you are verified.

The platform then immediately runs the model check. If it passes, the platform pins the commit as your approved version. To pin means to record its SHA, the unique ID of that commit.

If it fails
Ownership verification failed, Model check failed
How to add a file on Hugging Face Generic guide
  1. Open your repo and click the Files tab (it may be called Files and versions).
  2. Click Add file, then choose to create a new file.
  3. Type AGL_VERIFY.txt as the file name and paste the verification code as the content.
  4. Commit the file to the main branch.

Step 6: Run Diagnostics

The Diagnostics tab on your Profile checks a registered AG Champion from start to finish and tells you in plain language what to fix. It can take a few minutes, because the last check runs your AG Champion in the sandbox.

Tip

Diagnostics is read-only. It never changes your AG Champion, your repos or your verification state, so you can run it as often as you like.

What to do
  1. Open the Diagnostics tab.
  2. Pick the game.
  3. Click Run diagnostics.
  4. Read the report and fix what it reports. Run it again.
Where
The Diagnostics tab on your Profile.
How you know it worked
The report ends with RESULT: your model works correctly.
If it fails
Diagnostics says the model or data files are not on the server yet, Diagnostics says the sandbox is unavailable, Model check failed
The 7 checks Diagnostics runs Reference
  1. Registration: a model repo is registered for this game.
  2. Model repo access: the repo exists, is Gated, and the platform account has access.
  3. Ownership proof: the model repo (and the data repo, if set) are ownership-verified.
  4. Repository files: the files listed in config_model.json and config_data.json are present.
  5. Version and integrity: approved and current SHAs, the repo-change cooldown and your rated-games count (shown as Rated games since last revalidation: x / {{ tournament_min_rated_games|default:30 }}).
  6. Stored contract result: whether the model check last stored active, pending or failed.
  7. Live contract test: runs your load() and get_move() in the sandbox on three sample positions and checks that every move is legal.

Step 7: Play and compete

Warning

After you join a tournament, do not push any change to your AG Champion repo. A new commit disqualifies you automatically. Details: Version pinning.

What to do
  • Quick match: go to the Lobby and challenge another player. Your AG Champion plays automatically in real time.
  • Tournament: first play {{ tournament_min_rated_games|default:30 }} rated games in the Lobby. Then open a tournament and click Register or Join. When the tournament asks players to ready up, mark yourself Ready. The platform schedules and runs all matches automatically. The qualification rule is explained in Tournament qualification.
Where
The Lobby for quick matches and the tournaments page for tournaments. For how tournaments run, see How tournaments work.
How you know it worked
Your AG Champion plays its moves on its own. Results of rated games update your Elo. For how each move is generated, see During a game.
If it fails
I cannot join a tournament, Move timed out, or random moves are played for my AG Champion, Disqualified: SHA mismatch

Best practices

  • Load everything in load(). Load models, weights and opening books inside load(ctx), which runs once. Never read files inside get_move: that time is spent on every move and counts against your clock and the move timeout.
  • Stay well under the move time limit. Budget your search depth or inference time below the limit in Sandbox limits. If your AG Champion is too slow, random moves are played for it (see When a move fails).
  • Keep it lightweight. Keep your dependencies minimal and avoid anything that expects internet connectivity. If you like, note the versions you tested with in your repo's requirements.txt for your own reference.
  • Return a plain string in the right format. Always return a legal move as a plain string, in the format shown under Move format. Anything else is treated as no move.
  • Test before tournaments. Run Diagnostics, then play several quick matches in the Lobby to confirm your AG Champion responds correctly at game speed before you enter a tournament. The {{ tournament_min_rated_games|default:30 }}-game qualification window is the ideal calibration period.

Troubleshooting

Find the symptom, open it, and follow the fix. The steps above link here when something goes wrong.

The activation email did not arrive
  • Check your spam or junk folder. The email comes from agladiator.com.
  • Wait a few minutes. Delivery can take up to 10 minutes.
  • Still nothing? Contact support.
  • Your username is reserved while you wait, so you do not need to register again.
My repo is rejected (Repo ID rejected)
  • Enter the repo as username/repo-name. A huggingface.co model or dataset link is converted automatically. A Space URL is rejected.
  • A public model repo is rejected: set it to Gated first. The data repo is the opposite: it must be Public. See Repo access.
Model check failed
  • The Gladiator tab shows the reason. Typical causes: a syntax error, a missing load(ctx), invalid config_model.json, a file listed in data_files that is missing from the data repo, or a move that is not legal for one of the three sample positions.
  • Fix the repo, then click Verify Ownership (or Save and verify) again.
Invalid move returned
  • Confirm that your move string matches the expected format for the game. See Move format: UCI for Chess (for example e2e4) or four characters, from-square then to-square, for Breakthrough (for example a2a3).
  • Make sure you return a plain string: not a list, not a JSON object, not {"move": "..."}.
Data files not loading
  • Confirm that your data repo is Public on Hugging Face.
  • Check that the filenames in config_data.json and in data_files of config_model.json match exactly (case-sensitive) the filenames in your repo, and that your load() reads them from ctx.data_dir.
Ownership verification failed
  • Make sure AGL_VERIFY.txt is at the root of your model repo on the main branch, not inside a subfolder.
  • If you set a data repo, it needs its own AGL_VERIFY.txt with the same code.
  • The file must contain exactly the code shown on the Gladiator tab. If you re-saved a changed repo, a new code was issued. Use the new one.
  • The model repo must be Gated and you must have approved ArtificialGladiatorLeague in its Access settings. The data repo must be Public. See Repo access.
Diagnostics says the model or data files are not on the server yet
  • Log out and log in again, then run Diagnostics again. Logging in lands you on the Lobby, which loads your AG Champion and downloads your data repo files to the server in the background. Give it a minute before you re-run.
  • If it keeps saying the same thing, check the Repo File Status panel on the Gladiator tab for missing files.
Diagnostics says the sandbox is unavailable
  • This is a platform issue, not a problem with your AG Champion. Try again later.
I cannot join a tournament
  • The tournament page shows how many qualifying games you still need (for example "N games to go"). Play more rated games in the Lobby. Games played inside tournaments do not count{% if guest_mode_enabled %}, and neither do guest games{% endif %}.
  • If you see "Integrity check failed: your Hugging Face repository changed since it was approved", a new commit was found in your repo. Click Re-check Ownership on the Gladiator tab, then play your qualifying games again. See Version pinning.
  • If the page asks you to verify ownership, finish Step 5 first.
Move timed out, or random moves are played for my AG Champion
  • A move that takes longer than the server's move timeout ({{ sandbox_move_timeout|default:30 }} seconds) is cancelled, the sandbox container is restarted, and a random legal move is played for that turn. Reduce search depth, use a lighter model, or pre-compute in load().
  • If your code raised an exception, returned nothing or returned an illegal move, the platform plays a random legal move instead. Run Diagnostics to see the exact error.
  • If your AG Champion's last model check failed, no random move is played and you forfeit the game. Fix the problem and click Verify Ownership again.
  • The full behaviour is described in When a move fails.
Disqualified: SHA mismatch
  • You pushed a commit to your AG Champion repo after registering for the tournament. See Version pinning.
  • Even trivial changes (README edits, whitespace) produce a new SHA. Freeze the repo once registered.

Frequently asked questions

Can I use PyTorch or other libraries?

Only the libraries the sandbox image contains. They are listed under Sandbox limits. The sandbox has no network access, so packages cannot be installed at match time. Develop and test locally against the same libraries.

Do I need a Hugging Face account?

Yes, to create your model repo (and the optional data repo). The platform does not ask you for an API token. See Repo access.

Which of my repos must be Gated, and which must be Public?

See the table in Your two repos. The consequences are explained in Repo access.

Can I update my AG Champion between games (outside tournaments)?

Yes, you can update your AG Champion or change your repo links outside of tournaments. Changing your model repo ID resets your rated-games counter, and so does a new commit in your repo. See Tournament qualification and Version pinning.

More answers about games, time limits and thinking time are in the FAQ on How it works.
